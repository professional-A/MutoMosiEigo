# 人工知能概論 緊急対策：用語カード＋一問一答 実装仕様

**作成 2026-09-10（Opus）／実装担当 Sonnet／試験 9/14(月) 9:00**

## なぜ作るのか

既存の `tests/2026-9-ai-kakomon`（過去問90問）と `tests/2026-9-ai-ruiji`（類似90問）は
**ゼロから始める人にとって難しすぎる**。この科目は外国人教員による英語の授業で、
クラス全員が実質的に授業内容を受け取れていない状態にある。問1がいきなり
「教師あり学習の問題はどれか」で、教師あり学習が何かを知らない人には手がかりがない。

学習効果の面でも問題がある。正答率が50%を下回るとテスト形式の学習効果はほぼ消え
（`feedback-required-when-accuracy-below-50`）、学習が最速なのは正答率85%付近
（`optimal-difficulty-85-percent`）。現状は20〜30%の帯で、**最も伸びず最も心が折れる帯域**。

そこで既存2つの**手前に、易しい2層を挟む**。既存の180問は捨てない。

```
① 用語カード（新規・最優先） → ② 一問一答（新規） → ③ 過去問90（既存） → ④ 類似90（既存）
```

## 前提となる事実

- 本番は**多肢選択式・正誤判定式・対応付け式の3形式のみ**。記述・計算記入は出ない
  （教員告知で確定）。つまり**再認さえできればよく、自力で答えを作る必要は一度もない**
- 範囲は練習問題集90問に事実上確定している。**有限で数えられる集合**
- 全問ランダムに答えた期待値は 27.8/90（31%）。覚えた分はすべてその上に積み上がる
- **マッチング10問が最高効率**：推測10%→知識100%で9点動く。中身は定義の対応付けのみ

## 目標

満点は狙わない。**55〜65／90（60〜70%）** が3日半での現実的な着地点。
捨て問（t-SNE・DBSCAN・多重共線性・LOOCV など単発の細かい話）は最後まで
手が回らなければ推測でよい。そこに時間を使うよりマッチングと用語を固める方が点になる。

# 層① 用語カード

**ファイル**：`tests/2026-9-ai-yougo/data.json`
**storageKey**：`ai_yougo_v1`
**問数**：約120問（下記の用語 約60語 × 2方向）

## 形式

- 全問 `single` 型、選択肢4つ
- **双方向で出す**：「用語→意味」と「意味→用語」の両方（制御工学の `seigyogaku-vocab` と同じ方式）
- 誤選択肢は**同じリスト内の別の実在する用語／意味**から取る。でたらめな文を混ぜない
  （`competitive-lures-make-mcq-generative` — もっともらしい誤選択肢が「なぜ他が違うか」の
  検索を起こす）
- 解説は一行でよい。ただし**なぜそれが答えかが分かる一行**にする

## 決定的に重要な並び順

**易しい順・基礎から並べる。** 元の問題集の順序に引きずられないこと。
最初のセクションで正解が続くように設計する（`optimal-difficulty-85-percent`）。
セクション分けは下記のTier順にそのまま従う。

# 層② 一問一答

**ファイル**：`tests/2026-9-ai-ichimon/data.json`
**storageKey**：`ai_ichimon_v1`
**問数**：90問（既存90問と1対1対応）

## 何をするものか

**90問それぞれを「1文の事実」に還元して、その事実を直接問う。**
「Q17の答えはB」を覚えるのではなく「**癌検出では感度を重視する（見逃しが命取りだから）**」
を覚える。これなら本番で選択肢の並びや言い回しが変わっても効く。

### 層②と層③（過去問そのまま）の違い

| | 層③（既存の過去問） | 層②（これ） |
|---|---|---|
| Q17 | 「癌を検出するMLモデルを作っています。評価に使う指標はどれが好ましいですか」→ 正解率／感度／特異度／MSE | 「**見逃し（偽陰性）を絶対に避けたいとき重視する指標は？**」→ 感度（再現率）／適合率／正解率／特異度 |

**シナリオや引っかけを剥がして、事実だけを直接聞く。** これが層②の役割。

## 作り方

1. `tests/2026-9-ai-kakomon/data.json` の全90問と、その `note`（解説）を読む
2. 各問について、**解説に書かれている核心を1文の事実に圧縮**する
3. その事実を直接問う `single` 型の問題を1問作る（選択肢4つ。正誤問題由来のものは2択でよい）
4. 元の問題番号との対応を `note` の末尾に `（過去問 Q17 に対応）` の形で書く

**解答は既存 `2026-9-ai-kakomon/data.json` と矛盾させないこと。**
既存の解答キーは `docs/plans/2026-09-10-ai-final-exam-quiz.md` にある（Opus が導出し、
90問すべて実装と照合済み）。事実の内容を勝手に変えないこと。

## 並び順

**易しい順に並べ替える。** 元の問1〜54→正誤→マッチングの順を踏襲しないこと。
目安として次のセクション構成にする：

1. マッチング由来の10問（定義そのもの・最も易しい・最高効率）
2. 正誤問題由来のうち常識で解けるもの（CNN=画像、LLM=深層学習、教師なしは正解を与えない 等）
3. 基本概念（教師あり/なし/強化、分類/回帰、過学習/未学習）
4. 手法の識別（PCA・k-means・SVM・アンサンブル 等）
5. 評価指標
6. 計算を伴うもの（ベクトル長・パラメータ数・行列の形・Precision 等）
7. 探索・論理
8. 細かい・単発のもの（t-SNE・DBSCAN・多重共線性・LOOCV 等）＝ 捨ててよい層

セクションタイトルに難易度が分かる言葉を入れる（例：`01 まずここから：用語の対応`、
`08 余力があれば：細かい論点`）。**最後のセクションには「ここは捨ててよい」と明記する。**

# 共通ルール

- `.claude/skills/test-creation-workflow.md` に従う。テストごとの `index.html` は作らない
- **`input` 型は絶対に使わない。** 本番が選択式のみのため
- `"katex": true`（数式が出る）
- `subject: "人工知能概論"`、`pointsPerQ: 100`
- 日本語のみ。英語は併記しない（`match-the-language-of-the-real-exam`）
- 1問ごとの即時フィードバック（quiz-engine の標準動作）＋短い解説を必ず付ける
  （`immediate-feedback-halves-lure-intrusions`）
- **正誤判定形式で「誤り」が答えの問題は、解説に必ず正しい記述を書く。**
  偽の文を繰り返し読ませると真だと感じられるようになるため（錯覚的真実効果）
